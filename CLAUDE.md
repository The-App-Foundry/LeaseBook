## Project Overview

LeaseBook is a cross-platform property management application built with Tauri v2, React 19, TypeScript, and CSS. The application targets desktop (Linux, macOS, Windows), Android, and iOS platforms.

**Tech Stack:**

- **Frontend**: React 19 + TypeScript + Vite
- **UI Styling**: Component-specific CSS files with a custom bootstrap integration
- **Backend**: Tauri v2 (Rust)
- **Icons**: lucide-react
- **Package Manager**: pnpm 10.26.1

## Architecture

### Frontend Structure

The React application uses a component-based architecture with CSS-based styling:

- **Entry Point**: `src/main.tsx` imports Bootstrap CSS and global `src/App.css`
- **Global Styles**: `src/App.css` contains variables, resets, base typography, and common layouts
- **Component Organization**:
  - `src/components/ui/`: Reusable UI primitives (Button, Card, Badge, SearchBar, Sort)
  - `src/components/layout/`: Layout components (Header, FilterBar)
  - Each directory has an `index.ts` barrel file for clean imports

### Styling Patterns

All components use standard CSS with the following conventions:

1. **Component-Specific CSS**: Custom styling resides in a `.css` file next to the `.tsx` component and is imported directly (e.g., `import './Header.css'`).
2. **Static Styles**: Move all static styles into CSS classes.
3. **Dynamic Styling**: Only pass dynamic properties (e.g., dynamic color badges or custom dimensions) as inline `style` objects or CSS custom variables.
4. **Hover States**: Implement using standard CSS pseudo-classes (e.g., `:hover`) in the CSS file instead of React mouse event handlers.

### Layout System

- **Fixed Header**: The Header component is fixed at the top with `position: fixed` and `z-index: 20`
- **Content Area**: Main content uses `padding-top: var(--app-header-height)` to offset the fixed header
- **Responsive**: Components use `100vw`, flexbox, and responsive units

### Tauri Backend

- **Entry Point**: `src-tauri/src/lib.rs` — initializes the Diesel/r2d2 SQLite connection pool, runs embedded migrations on startup, manages the pool as Tauri state, and registers all commands
- **Commands**: `src-tauri/src/commands.rs` — all `#[tauri::command]` handlers; each acquires a connection from the pool and delegates to `db/operations.rs`
- **Database Layer**: `src-tauri/src/db/operations.rs` — Diesel CRUD functions for leases, managers, and the `leases_managers` join table; `src-tauri/src/db/mod.rs` re-exports them
- **ORM Models**: `src-tauri/src/models.rs` — Diesel `Queryable`/`Insertable`/`AsChangeset` structs; `UpdateLeaseInput` / `UpdateManagerInput` are owned Tauri-argument types that map to borrowed `UpdateLease` / `UpdateManager` changesets
- **Schema**: `src-tauri/src/schema.rs` — Diesel-generated table macros (do not edit by hand; regenerated by `diesel migration run`)
- **Migrations**: `src-tauri/migrations/` — timestamped up/down SQL files; embedded at compile time via `embed_migrations!`
- **Spreadsheet Import Pipeline**:
  - `parser.rs` — uses `calamine` to open `.xlsx`/`.ods`/etc. and produces a `Spreadsheet` value (sheets → rows → cells)
  - `spreadsheet.rs` — plain data types (`Spreadsheet`, `Sheet`, `Row`, `Cell`)
  - `prop_map.rs` — maps a `Spreadsheet` + user-supplied column mapping → `Vec<property::Lease>`
  - `property.rs` — the intermediate `Lease` struct used during import (distinct from `models::Lease`)
- **Plugins**: `tauri-plugin-dialog`, `tauri-plugin-opener`, `tauri-plugin-fs`
- **Configuration**: `src-tauri/tauri.conf.json` — dev server port 1420, CSP `default-src asset: https://asset.localhost data: https`, asset protocol scoped to `$HOME/.local/share/com.openworld.leasebook/**`

#### Adding a new Tauri command

1. Add the DB operation to `src-tauri/src/db/operations.rs`
2. Add the `#[tauri::command]` fn to `commands.rs`
3. Register it in the `invoke_handler!` list in `lib.rs`

#### Adding a database migration

```bash
cd src-tauri
diesel migration generate <name>
# edit up.sql / down.sql
diesel migration run   # also regenerates schema.rs
```

### Build Process

1. **Development**: Vite dev server runs on port 1420, Tauri watches Rust changes
2. **Production**: `pnpm build` runs TypeScript compilation + Vite build, then Tauri bundles the app
3. **Vite Config**: Uses `@vitejs/plugin-react`, configured to ignore `src-tauri/` in watch mode

## Theme Configuration

The theme object (`src/styles/theme.ts`) provides:

- **Colors**: primary, background, text, surface, muted, border, success, danger, focus
- **Typography**: System font stacks for body and mono
- **Radii**: sm (6px), md (8px), lg (12px)

TypeScript autocomplete is enabled via `src/styles/styled.d.ts` which extends the `DefaultTheme` interface.

- **Prettier**: Configured for 100-char line width, single quotes, trailing commas, LF line endings

## Important Notes

- Main branch is `base` (use this for PRs)
- All UI components should use the theme system rather than hardcoded colors
- Use transient props (`$prop`) in styled-components to avoid React DOM warnings
- Timestamps in the DB are Unix epoch seconds stored as `i32`; the frontend converts them with `unixToIso` in `App.tsx`
- `Lease.status` is derived client-side from `expiration_date` — expired → `'prospect'`, active → `'qualified'`; there is no status column in the DB
